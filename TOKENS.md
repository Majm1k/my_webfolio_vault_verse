# TOKENS.md

Всё живёт в `css/tokens.css` как CSS-переменные. Вложенность CSS не используется.

Источники: кегли, цвета и радиусы сняты с макета «Макет как должно выглядеть».
Брейкпоинты, сетка, кривые, длительности и обе типографические зависимости —
из `apple-reference.md`.

Замер макета: рендер шириной 681px, поле контента от 113 до 563px.
Это даёт ширину контента ≈ 1260px при вьюпорте 1920 — совпадает с
`--global-content-max-width` из референса. Дальше все кегли пересчитаны
с коэффициентом 1920/681 ≈ 2.82. Значения округлены до шкалы референса,
куда попали почти точно.

## 2. Типографика

Шкала макета совпала со шкалой референса и переносится целиком — вместе
с двумя зависимостями. Единственное отклонение: **лид первого экрана 28px,
а не 21px**. Первый замер занижал кегли, потому что считал среднюю ширину
знака по латинице (0.5em). В кириллице она около 0.6em — знаки `ш`, `щ`, `ы`,
`м`, `ж` заметно шире. С поправкой строка лида в 67 знаков шириной 1120px
даёт 28px, а не 21px. Остальные ступени пересчёт подтвердил.

Зависимости:

- **трекинг меняет знак с кеглем**: −0.015em на 96px → +0.011em на 21px;
- **межстрочный сжимается с ростом кегля**: 1.04 на 96px → 1.38 на 21px.

| Токен | 1441+ | ≤1068 | ≤734 | line-height | letter-spacing | weight | Где |
|---|---|---|---|---|---|---|---|
| `--fs-display` | 96 | 80 | 56 | 1.04 | −0.015em | 800 | H1 «Рузайкин Дмитрий» |
| `--fs-h2` | 48 | 40 | 32 | 1.08 | −0.003em | 600 | заголовки секций |
| `--fs-h3` | 32 | 28 | 24 | 1.125 | +0.004em | 600 | заголовки принципов |
| `--fs-card-lg` | 28 | 24 | 21 | 1.14 | +0.007em | 600 | карточки «Больше» |
| `--fs-card` | 21 | 21 | 19 | 1.19 | +0.009em | 600 | карточки «Факты», вопросы FAQ |
| `--fs-intro` | 28 | 24 | 19 | 1.38 | +0.004em | 400 | лид первого экрана |
| `--fs-body` | 17 | 17 | 14 | 1.24 | −0.022em | 400 | подписи Behance, подписи принципов |
| `--fs-body-long` | 17 | 17 | 15 | 1.47 | −0.022em | 400 | оборот карточек, оверлей, ответы FAQ |
| `--fs-caption` | 12 | 12 | 12 | 1.33 | +0.06em | 600 | `NEOLINE`, теги, `01 / путь` |

Ширина текстовой колонки в оверлее и на обороте карточки — `max-width: 60ch`.

`--fs-caption` набирается прописными (`text-transform: uppercase`), поэтому
трекинг у неё заметно больше формулы — это компенсация капители, не нарушение.

Начертания: 400 / 600 / 800. Тонких нет.

### Шрифт

**Inter**, переменное начертание 400–800, self-hosted: `fonts/inter-cyrillic.woff2`,
`inter-latin.woff2`, `inter-latin-ext.woff2` с `unicode-range` на каждый поднабор
и `font-display: swap`. Внешнего CDN нет — Pages отдаёт файлы сам.
Запасной стек: `system-ui, -apple-system, "Segoe UI", Roboto, Arial, sans-serif`.

Трекинг из таблицы сдвинут на −0.003em: у Inter метрики шире SF Pro.

## 3. Сетка и брейкпоинты

Формула ровно как в `overview.built.css`: ширина контента — меньшее
из максимума и 87.5% экрана, поля — половина остатка.

```css
--content-max: 1260px;                        /* обычные секции */
--hero-max: 1680px;                           /* лента первого экрана */
--content-w: min(var(--content-max), 87.5%);  /* --responsive-content-width */
--gutter: 6.25%;                              /* (100% − 87.5%) / 2 */
--rail: max(6.25%, calc((100% - var(--content-max)) / 2));
```

`--rail` — поле полноширинных каруселей: и внешний отступ трека,
и его `scroll-padding-inline`.

Брейкпоинты — четыре точки из референса. Мобильные через `max-width`,
десктопные через `min-width` на +1px:

| Точка | Мобильный запрос | Десктопный запрос |
|---|---|---|
| 480 | `max-width: 480px` | `min-width: 481px` |
| 734 | `max-width: 734px` | `min-width: 735px` |
| 1068 | `max-width: 1068px` | `min-width: 1069px` |
| 1441 | `max-width: 1440px` | `min-width: 1441px` |

## 6. Кривые

```css
--ease-main:    cubic-bezier(.4, 0, .6, 1);      /* переходы состояний */
--ease-soft:    cubic-bezier(.25, .1, .3, 1);    /* мягкая, фоны */
--ease-card:    cubic-bezier(0, 0, .5, 1);       /* ховер карточек */
--ease-enter:   cubic-bezier(.23, 1, .32, 1);    /* появление — из emil-design-eng */
--ease-stagger: cubic-bezier(.45, 0, .55, 1);    /* easeInOutQuad — из main.built.js */
```

Появление при скролле идёт по `--ease-stagger`. Это easeInOutQuad: именно её
подставляет модуль `StaggeredFadeIn` в `main.built.js`
(`easeFunction: "easeInOutQuad"`). Первоначально была выбрана `--ease-enter`
из скилла, но исходники Apple оказались весомее. Чтобы вернуть прежнюю,
достаточно поменять одну переменную в `base.css`.

Правило разделения: состояния и ховеры — `--ease-main`, появление —
`--ease-stagger`. В одном взаимодействии не смешиваются.

## 7. Длительности

Опорная — `.24s`. Всё, что пользователь трогает чаще, короче.

```css
--dur-press:    80ms;    /* :active, диапазон 20–80 */
--dur-instant: 100ms;    /* стрелки каруселей, цвет */
--dur-xs:      .12s;
--dur-s:       .16s;
--dur-base:    .24s;     /* опорная */
--dur-hover:   .3s;      /* ховер карточки */
--dur-overlay: .344s;    /* оверлей, фоны */
--dur-l:       .5s;      /* крупные блоки */
--dur-flip:    .44s;     /* переворот карточки «Факты» */
```

Появление при скролле — намеренно разные длительности, не выравнивать:

```css
--reveal-opacity-dur:   .9s;
--reveal-translate-dur: .7s;
--reveal-translate-y:   30px;
--reveal-stagger:       .15s;
```

## 8. Панель поверх страницы

Тайминги `.modal` заданы на самом блоке, а не в общем слое: они нужны
только ему, и `modal.js` читает `--modal-dur`, чтобы снять `hidden`
ровно по окончании движения.

```css
--modal-dur:  0.8s;
--modal-ease: cubic-bezier(.65, 0, .35, 1);   /* из overview.built.css */
```

Подложка гаснет вдвое быстрее панели (`calc(var(--modal-dur) / 2)`),
`visibility` снимается только в конце — иначе панель пропала бы рывком
посреди движения.

## 9. Что перенесено из исходников Apple

Сверено по `overview.built.css`, `main.built.js` и `globalheader.css`.

| Наше | Оригинал | Значение |
|---|---|---|
| появление при скролле | `StaggeredFadeIn` | задержка 0.15, прозрачность 0.9s, сдвиг 30px за 0.7s, easeInOutQuad, старт `t − 85vh` |
| раскладка трека каруселей | `.scroll-gallery` | `padding: 10px rail 30px` и гасящие отрицательные поля |
| стрелки | `.paddlenav .paddlenav-arrow` | `background/color/opacity 100ms linear`, выключенная `opacity: .42` |
| блок стрелок | `.scroll-gallery-paddlenav` | `opacity .2s ease-out` |
| круглые кнопки карточек | `.tile-button` | `background-color 100ms linear` |
| крестик панели | `.ric-modal-close-icon` | `color 100ms linear, background 100ms linear` |
| панель поверх страницы | `.modal` | `0.8s cubic-bezier(.65, 0, .35, 1)`, подложка вдвое быстрее, `visibility` в конце |
| ховер карточки | `.card-hover` | `transform .3s cubic-bezier(0, 0, .5, 1), background-color .344s ease` |
| фон карточки | `.card` | `background-color .344s ease` |
| аккордеон | `.accordion-tray` | `height ease-in-out`, `--accordion-transition-duration: 400ms` |
| ссылки шапки | `.globalnav-link` | `color .32s cubic-bezier(.4, 0, .6, 1)` |

Главное в `StaggeredFadeIn` — наблюдают за **группой**, а не за элементами.
Компонент висит на контейнере, внутри собирает `[data-staggered-item]`
и при срабатывании заводит одну шкалу времени, где у элемента с номером
`i` старт сдвинут на `i × 0.15s`. Своих наблюдателей у элементов нет,
и для каруселей это принципиально: карточка, уехавшая вбок за край
экрана, для наблюдателя невидима, и при поэлементном слежении появлялась
бы не вместе с блоком, а в момент, когда её пролистают стрелкой.

Не переносилось, потому что таких блоков у нас нет: `tabnav`, `.index`
(меню глобальной навигации), проигрыватели `inline-media` и `media-block`,
галереи `product-tile`, `thumbnail-*`. Весь `globalheader.css` — это
флайауты, поиск и корзина Apple; применима оттуда одна строка про цвет
ссылки.

Каскад `.card-overlay` (`transform .414s ... .344s` у содержимого) в
оригинале относится к раскрытию карточки на месте. Мы этот блок заменили
на панель поверх страницы, а у `.modal` в исходнике каскада содержимого
нет — только сдвиг самой панели. Поэтому его и у нас нет.

## 10. Буквы заголовков

```css
--c-letter-0 … --c-letter-4      /* палитра букв */
--dur-letter:     0.72s;
--letter-stagger: 0.045s;
--ease-back: cubic-bezier(.34, 1.56, .64, 1);
```

Все шесть заголовков (первый экран и пять секционных) разбираются на
буквы: каждая влетает крупнее, повёрнутой и цветной, перебирая символы,
потом садится в нормальный размер и обычный цвет. При наведении то же
повторяет одна буква — та, на которую навели.

Запуск по появлению заголовка в кадре, тем же порогом, что и остальное
появление на странице. Заголовок первого экрана виден сразу и стартует
сразу — отдельного случая для него нет. До запуска заголовок спрятан
целиком (`visibility`), это `.pre-animation` из `overview.built.css`:
иначе буквы отыграли бы, пока блок ещё за экраном.

Головы секций выведены из общего появления (`data-reveal` с них снят):
иначе блок плавно всплывал бы вместе с буквами и обе анимации мешали
друг другу.

На светлом фоне подставляется вторая, более плотная палитра: исходные
цвета подобраны к чёрному и на `#f5f5f7` почти не видны.

Маркер за словом («Факты.», «вопросы?») заезжает вместе со своей первой
буквой — `background-size` от нуля. Без этого его подложка нарисована
с самого начала, а буквы на ней ещё не пришли, и посреди каскада висит
пустая цветная плашка.

Разброс размера, наклона и цвета считается от номера буквы, а не через
`Math.random`: картинка должна быть одной и той же при каждой загрузке,
иначе её не сверить на скриншотах.

В кадрах намеренно нет `to`: без него браузер доводит анимацию до
собственных значений элемента, и не приходится дублировать в CSS ни цвет
заголовка, ни `transform: none`. Две ступени внутри: прозрачность
набирается к 25%, цвет держится до 55% — иначе он размазан по всей
анимации и акцент выцветает раньше, чем его успеваешь заметить.

Повтор по наведению — те же кадры под другим именем: смена
`animation-name` перезапускает анимацию, иначе повторное наведение на ту
же букву ничего бы не дало.

Вместе с подскоком идёт перебор символов. Настоящая буква не
подменяется, а прячется через `visibility` — её бокс остаётся на месте
и держит ширину; перебираемый знак висит поверх по центру, вне потока.
Поэтому строка не дёргается ни на кадр: замер по `offsetLeft` всех
пятнадцати букв за весь перебор даёт 0px. Побочно текст заголовка
остаётся целым в DOM даже посреди анимации — скопировать можно всегда.

Широкие знаки (`$ & @ % —`) из набора выкинуты: знак вне потока, и тот,
что шире своего бокса, наезжает на соседей — на кегле 94px это выглядит
поломкой, а не помехами.

Перебор запускается по `animationstart`, а не своим таймером: событие
приходит уже после задержки, поэтому перебор сам попадает в такт
каскаду на загрузке и в подскок по наведению — и останется в такте,
если поменять задержку в CSS.

Отыгравшая буква помечается `data-settled` и больше не анимируется.
Без этого снятие `data-bounce` возвращало `letter-in` вместе с его
задержкой, а при `fill-mode: both` буква на время задержки берёт первый
кадр — то есть после каждого наведения пропадала и появлялась заново.

Каждая буква — `inline-block` (иначе не применится `transform`), поэтому
слова обёрнуты в `.hero__word` с `white-space: nowrap`: без этого строка
рвалась бы посреди слова. Проверено до 360px — ни одно слово не рвётся.

`--ease-back` с перелётом — своя кривая, в исходниках Apple такого приёма
нет. Палитра тоже своя: в макете этого блока нет, а два имеющихся
акцента — маркеры за «Факты.» и «вопросы?» — взяты первыми, остальные
подобраны к ним в том же мягком регистре.

Без JS заголовок остаётся обычным текстом. Программе чтения с экрана
отдаётся исходная строка через `aria-label`, чтобы она не читала буквы
поодиночке.

## 12. Что требует подтверждения

- HEX маркеров (голубой `#7EC8F0`, розовый `#FFAAD0`) и звезды `#FF5FA2` —
  сняты пипеткой с рендера, не из исходника.
- `--c-surface-dark` (`#1D1D1D`) и `--c-card-dark` (`#0D0D0D`) различаются
  на глаз слабо; если в макете это один цвет, свести к одному токену.

Цвета нумерации принципов взяты из присланных значений: `#008457`, `#E1004B`,
`#A36500`. Подписи к ним в тексте («оранжево-красный», «синий») с этими
значениями расходятся — верны сами значения.
